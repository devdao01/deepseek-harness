# Agent Note: Preset-conventional default workspaces

Status: implemented

English | [中文](2026-08-21-preset-conventional-default-workspaces.zh.md)

## Problem

Authoring a preset with `agentPreset.copy` created a composition but left the user to make and register a workspace for it by hand before any session could land somewhere sensible. There was no convention tying a preset to a directory, so a freshly copied `accounting` preset started sessions in the host process cwd like every other unnamed create. The user story is direct: creating preset `accounting` should also give it a default workspace at `~/workspace/accounting`, and starting a session under that preset should land there without the client having to name a workspace.

## Decision

A conventional mapping — preset `<id>` ⇄ `<presetWorkspacesRoot>/<id>` — provisioned at copy time and honored at session-create time.

**Config and resolution.** A new `ApiProxyService` config field `presetWorkspacesRoot?: string` (schemastery `z.string()`, cordis-changeable) names the root. Resolution is an explicit load-time step, not a hidden `??`: `resolvePresetWorkspacesRoot(configured, os.homedir())` maps absent → `<home>/workspace`, a `~/` prefix → home-relative, and requires any other value to be absolute, throwing on a relative value so misconfiguration fails loud at construction rather than silently rooting workspaces at the process cwd. The pure resolution, the id-safety check, and the id→path join live in the gated `src/preset-workspace.ts` (per-file 100% coverage); `createApiProxy` calls the resolver once at construction, and the resolver is idempotent on an already-absolute value so re-resolving a plugin-resolved root is a no-op.

**`agentPreset.copy` provisions and persists.** After the preset copy succeeds, the handler computes `<root>/<agentPreset>`, `mkdir -p`s it, creates-or-adopts a workspace over it through the same `ensureWorkspace` chain `workspace.create` uses (idempotent: a re-copy or an existing directory adopts rather than fails), and stamps the workspace's canonical path onto the new preset's metadata via `AgentPresets.setWorkspacePath`. The response grew from `{ agentPreset }` to `{ agentPreset, workspace: WorkspaceView }`. The id is checked with `isPresetWorkspaceIdSafe` — rejecting a separator or a `.`/`..` segment with `agent-preset-invalid` — before anything is copied, so a dangerous id never reaches the roster or a `join`. Copy-then-provision-then-stamp is one operation: if provisioning OR the stamp fails after the preset was copied, the just-copied preset is removed (rollback through the authoring `remove` path) and the call answers `directory-create-failed` naming the path.

**The link is persisted, not only conventional.** The preset directory's metadata file (`preset.yml`) gains an optional `workspacePath` (absolute; a relative or malformed value reads as absent, the same non-fatal degradation as the display fields). `AgentPreset` and the wire `AgentPresetEntry` carry it, `agentPreset.list` returns it, and `AgentPresets.setWorkspacePath(id, path)` (a narrow authoring write in `dsh-agent-presets`, guarded to `user` presets under the writable root like `remove`) stamps it while preserving the preset's existing display text. Discovery already spreads metadata onto `AgentPreset`, so the field flows through once the metadata reader and the type declare it.

**`session.create` preset default prefers the stored path.** The cwd chain gained one step before `workspace?.path ?? cwd ?? defaults.cwd`: when a create names neither a `workspaceId` nor a `cwd` but does name an `agentPreset`, the handler resolves a lookup path — the preset's stored `workspacePath` when it publishes one, else the recomputed `<root>/<agentPreset>` convention (only for a `isPresetWorkspaceIdSafe` id) — and looks up the registry for a workspace at that canonical path. Found → it treats it exactly as a named workspace: the session attaches and takes its path as cwd, reusing the existing attach path rather than only setting cwd. A missing registration (or a directory that no longer exists — `resolveByPath` rejects on a `realpath` ENOENT, which is caught) falls through to `defaults.cwd`; only `copy` provisions, so a deleted registration stays the user's choice and is never auto-created. A create without an `agentPreset` (the DEFAULT preset) gets no lookup. The registry read is guarded by `ctx.get('workspaceRegistry')` and the stored-path read by `ctx.get('agentPresets')`, so a deployment or test without either mounted simply skips the step.

## Alternatives considered

**Auto-mkdir the conventional directory inside `session.create` when it is missing.** Rejected: a session-create that silently recreates a directory the user deleted would fight the user's intent, and the registry is the record of what workspaces exist. Only `copy` — the explicit authoring act — provisions; `session.create` reads.

**Resolving `presetWorkspacesRoot` with a hidden `?? join(homedir(), 'workspace')` inside `run()`.** Rejected per the repo's "defaulting is an explicit resolve step, never a hidden `??` inside run" rule, and because a relative misconfiguration would then silently root workspaces at the process cwd. The explicit resolver throws at load instead.

**Returning only `{ agentPreset }` and letting the client fetch the workspace via `workspace.list`.** Rejected: the copy is the commit point that knows the provisioned workspace, and echoing it lets the client group the new preset's workspace without a follow-up round-trip — the same reasoning `session.create` already uses to echo the resolved preset.

**Validating the id only through authoring's own preset-id rules.** Rejected as insufficient for the path `join`: the containment guard must not trust that authoring forbids separators or `..`, so `isPresetWorkspaceIdSafe` re-checks before building any filesystem path.

**Folding the workspace-path stamp into the `copy` call for a single atomic write.** Tempting — no window where the preset exists without its `workspacePath` — but the canonical path is only known AFTER provisioning (`ensureWorkspace` returns the realpath'd directory), so stamping must follow the copy. `setWorkspacePath` is therefore a separate authoring write, and a stamp failure joins provisioning failure on the rollback path. The interim window is benign: a preset copied but not yet stamped resolves through the conventional fallback, which points at the same directory.

**Storing the pre-`realpath` conventional path to let `copy` stamp before provisioning.** Rejected: `session.create` compares against the registry's canonical (realpath'd) paths, and storing the conventional spelling would read differently on a symlinked root (macOS `/tmp` → `/private/tmp`). Stamping the provisioned workspace's own `path` keeps the stored value exactly what a later lookup resolves.

## Consequences

Creating a preset now yields a ready workspace, the link is persisted on the preset, and a preset-only session lands in it — the user story end to end. `presetWorkspacesRoot` is the one new knob; its default keeps zero-config deployments at `~/workspace/<preset>`. The wire changes are the copy response (`{ agentPreset, workspace }`) and the new `AgentPresetEntry.workspacePath`; the `dsh-client-connection` fixture mirrors both (its `copy` stamps a fake path and `list` surfaces it), and the apiproxy carrier test stubs were updated. `preset.yml` gains a `workspacePath` key, but the metadata reader ignores unknown/malformed values, so no on-disk format version is involved; the feature is not model-visible and emits no session event, so no snapshot fixture and no `SESSION_FORMAT_VERSION` bump either. `agentPreset.copy` now depends on a mounted `workspaceRegistry` (always present in production, in the service inject list) and the roster's `setWorkspacePath`; the preset-only unit harness opts the registry in only where a copy is exercised. Provisioning adds a `mkdir`, a registry write, and a metadata write to each copy, and rollback adds a preset remove to the rare failure path; all are bounded and local. The stamp is a metadata-file rewrite that reads and re-renders the preset's `preset.yml`, preserving its name and description.
